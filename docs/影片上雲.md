# 影片上雲（Google Drive）

86GB 課程影片目前只活在一顆外接硬碟上。這份文件講**怎麼把它複製一份到 Google Drive**、
會吃掉多少流量、斷了怎麼接回去，以及 `data/drive-map.json` 怎麼餵給播放器。

> **先講清楚一件事：這裡的「雲」不是 Cloudflare。**
> `CONTEXT.md` 的鐵則沒有變——**影片永不進 Cloudflare Pages**
> （`scripts/cloud/build-dist.mjs` 看到任何影片副檔名會直接中止建置）。
> 上的是**你自己的 Google Drive 個人空間**（5 TB，目前用掉 18.2 GiB）。
> Feb 只保存一張「集數代號 → Drive 檔案 id」的對照表，
> **一個位元組的影片都不經過我們的伺服器。**

---

## 1. 為什麼要做這件事

| 現況 | 上雲之後 |
|---|---|
| 影片只有一份，硬碟壞了就沒了 | 多一份離站備份 |
| iPad 出門看不到影片（3GB 裝不下，Safari 又一定會複製檔案） | 影片從 Drive 串進 **Feb 自己的播放器**（L3，§10）；退路是 Drive 內嵌預覽 |
| 雲端模式的集數 chip 點下去只有「用 VLC 開」 | 點下去就是播放器：章節時間軸、2 倍速、續播記憶都在 |

**不做什麼**：不讓影片經過 Cloudflare（不代理、不當靜態資產）、不把 Drive 檔案設成公開連結。
L3 的串流是**瀏覽器直接跟 Google 要**，我們只出一張對照表與一條 Service Worker 路由。理由見 §7、§10。

## 2. 前置：gws 要先登入

```bash
gws auth status        # 看得到 has_refresh_token: true 就可以了
gws auth login         # 沒登入或權杖過期（invalid_grant）時跑這個
```

登入這件事**只能你自己做**——腳本不碰、也不會去讀任何權杖或密碼。
腳本開跑的第一件事就是 `gws drive about get`，沒登入會立刻停在那裡，
不會傳到一半才失敗。

> ### ⚠ 家裡的網路是 iPhone 熱點
>
> **92.42 GB 會從你的手機門號走掉。** 上傳前先確認：
> 1. 這個月的行動數據額度夠不夠（吃到飽也可能有「超量降速」的門檻）
> 2. iPhone 的個人熱點會不會因為過熱或省電自己斷線

> 腳本內建一道閘門：**單次超過 5 GiB 一定要 `--yes`**，

> 課程最小的一包（115春矩陣）就已經 7.87 GiB——換句話說，
> **每一次真的上傳都會撞到那道閘門**，這是刻意的：手滑打不出 86GB。

## 4. 指令

```bash
# 先看一眼，什麼都不做（不出網、不建資料夾、不寫帳本）
python scripts/drive-upload.py --dry-run
python scripts/drive-upload.py --only 115春矩陣 --dry-run

# 真的傳一個課程（建議做法：一晚一包）
python scripts/drive-upload.py --only 115春矩陣 --yes

# 先傳三支試水溫，確認速度與穩定度
python scripts/drive-upload.py --only 115春矩陣 --limit 3 --yes

# 對帳：只檢查雲端大小對不對，不上傳
python scripts/drive-upload.py --verify
```

| 旗標 | 意思 |
|---|---|
| `--only <子字串>` | 只處理課程路徑（或檔名）含這段字的。`--only 電子` 會同時吃到 114暑電子與 115暑電子；要精準就寫 `--only 115暑電子` |
| `--limit N` | 本次最多上傳 N 支。表格仍然顯示整個課程的缺口，底下會加一行說明兩者的差別 |
| `--dry-run` | 只盤點。**一個資料夾都不建、帳本一個字都不寫** |
| `--verify` | 只對帳大小，不上傳。會順便把雲端查到的檔案 id 收進帳本 |
| `--yes` | 確認送出超過 5 GiB 的批次 |
| `--root <名稱>` | Drive 上的根資料夾，預設「Feb 影片備份」 |
| `--retries N` | 單支影片的重試次數，預設 2 |
| `--min-kbps K` | 換算單支 timeout 用的保守下限速度，預設 200 KB/s。熱點特別慢時調小 |

**推薦的排程**（由小到大，先確定管線會動再上大的）：

```
115春矩陣 (7.87)  →  多益 (8.84)  →  114暑電子 (10.35)  →  115暑微方 (10.25)
                  →  115春微方 (11.63)  →  115暑線代 (13.00)  →  115暑電子 (24.13)
```

## 5. 斷了怎麼辦

**直接把同一行指令再打一次。** 沒有別的步驟。

續傳的粒度是**一支影片**，機制是這樣：

- 每上傳成功一支，`data/drive-map.json` 就落地一次（先寫 `.tmp` 再 `os.replace`，
  斷電也不會留下半份 JSON）。重跑時帳本裡有、而且大小相同的，直接跳過。
- **帳本掉了也不會重傳。** 每個課程開跑前腳本會先 `list` 一次雲端那個資料夾，
  同名同大小的檔案直接認領回帳本。實測把 `drive-map.json` 整個刪掉再跑，
  結果是「0 支待上傳」，一個位元組都沒有重送。
- 斷在半路的那一支會在雲端留下一個**大小不對**的殘檔。腳本會報
  `尺寸不符` 並跳過它，**不會自己去刪雲端的檔案**——刪除一律你自己來。
  到 Drive 把訊息裡那個 id 刪掉，再跑一次就會重傳。

### 為什麼不是逐 byte 續傳

`gws` 0.22.5 只支援 multipart 上傳（`gws drive files create --upload --dry-run`
回的是 `is_multipart_upload: true`，沒有 `uploadType=resumable` 的開關）。
真正的分塊續傳要自己拿 OAuth access token 去打 resumable endpoint，
**那等於把你的權杖抓在腳本手上，不做**。

代價講清楚：一支影片平均 915 MB，斷在 90% 的話那 90% 要重來。
所以 `--retries` 預設 2、每次退避 15 秒往上加，而且建議一次只做一個課程。

## 6. `data/drive-map.json`：帳本長什麼樣、怎麼餵播放器

```json
{
  "folder": "16c2yRFCVGSaiRioZfBCpBjRORBB-zpOl",
  "updated": "2026-09-02T05:50:40.133Z",
  "folders": {
    "線代": "1urVuAYmXSHTHYwZdU84WpM4V4Sz7KLkR",
    "線代/115春矩陣": "1fkOA0MOV56upCIkfPwsP0CTDS9byzQ9p"
  },
  "files": {
    "115春矩陣01": {
      "id": "1AbC…",
      "name": "115春矩陣(喻)01 (下)P.247~P.300 矩陣代數運算.mp4",
      "size": 878751508,
      "md5": "b48a729b2afb50849c0bc469a899f818",
      "series": "線代/115春矩陣",
      "parent": "1fkOA0MOV56upCIkfPwsP0CTDS9byzQ9p",
      "uploaded": "2026-09-02T06:11:04Z"
    }
  }
}
```

| 欄位 | 意義 |
|---|---|
| `folder` | Drive 上的根資料夾 id |
| `folders` | `<科目>` 與 `<科目>/<期別>` 的資料夾 id。有了它就不必每次重新查 |
| `files` | **鍵是集數代號**，值是那一集在 Drive 的身分證 |
| `files[].md5` | Drive 回的 `md5Checksum`。目前只存著，`--verify` 比的是 `size` |
| `files[].uploaded` | 這支是這個腳本傳上去的時間。從雲端「認領」回來的沒有這個時間，會是空字串 |

### 鍵為什麼是那個樣子（這是整份文件最容易出錯的地方）

集數代號用的是 `site/js/07-disk.js` 的 `diskKey()`（內含 `05-media.js` 的 `spNorm()`）
**逐行移植的 Python 版**，不是「等價重寫」：

- 拔掉講師標記：`115春矩陣(喻)01` → `115春矩陣01`
- 拔掉最後一集的尾綴：`115春矩陣10-The End` → `115春矩陣10`
- 只留「年份＋季別＋科目＋兩位數字」，後面的頁碼與標題全部丟掉

**為什麼非得一模一樣**：播放器問的是 `spNorm(e.code)`（`09-render-study.js` 的
`LOCAL[spNorm(code)]`、`openCompanion(code)`）。帳本的鍵差一個字，那一集在
播放器眼中就等於沒上雲。

實測對帳（2026-09-02）：

- 101 支檔名 → 101 個唯一代號，**零撞號**（撞號腳本會直接中止，不會讓兩支互相覆蓋）
- 與 `data/videos.json` 的 `istudy.byChapter` 對得上 **96/101**；
  差的 5 支（115暑微方 19–22、23）是**課表本來就沒收錄**，不是鍵對不上
- 與媒體伺服器 `state.json` 的 `spNorm(code)` 有 **1 支不同**：
  `115暑微方23`。補習班把註記塞進 code 欄位本身
  （`115暑微方23<黑板課程&堂數錯誤>`），而 `spNorm` 只拔小括號、不拔角括號。
  **不同的是 state 那一側**——課表與作戰地圖的集數 chip 寫的都是乾淨的
  `115暑微方23`，所以帳本站在檔名這一側是對的。
  腳本會把這種分歧印成一行診斷，將來檔名規則再變時有人看得到。

### 怎麼接到播放器上

**已經接好了（2026-09-02，L3）**，而且不是只給一條連結——影片回到 Feb 自己的
播放器，章節時間軸、2 倍速、續播記憶全部照舊。做法見 §10。

**`data/drive-map.json` 會自動被帶上 Cloudflare**：它符合
`scripts/cloud/build-dist.mjs` 的 `ALLOW` 第一條（`data/<name>.json`、深度 1），
下次跑 `build-dist` 就會進 `dist/`。它跟其他所有教材一樣**站在 `_middleware.js` 後面**
（官方文件確認 Pages「would default to serving your Pages Functions ahead of
static assets」，而 `dist/_routes.json` 把這件事寫死），
沒有通過 Access 驗章的人一個字都看不到。

## 7. 安全：三件不可以做的事

1. **絕對不要把 Drive 上的影片設成「知道連結的任何人」。**
   那會讓 `drive-map.json` 從「一張沒有用的 id 清單」變成「一份公開的 86GB 教材種子」。
   維持預設的「只有我」——這樣 Drive 自己就是**第二道門**：
   即使 `drive-map.json` 外流，沒有你的 Google 帳號還是打不開任何一支。
2. **不要把 Drive 的權杖／client secret 放進 repo。** 腳本完全不碰它們，
   認證從頭到尾由 `gws` 自己管（`C:\Users\User\.config\gws\`）。
3. **不要讓 `drive-map.json` 變成公開檔案。** 它現在是 `data/*.json`，
   會跟考古題、招生簡章走同一條路：`_middleware.js` 守全站，沒設定就全鎖。
   這條不必特別做什麼——**只要不去替它開例外**就好。

檔名本身就是個人資料（哪一堂、講到第幾頁），照 `CONTEXT.md` 的
「個人教材不得匿名可讀」處理，跟考古題 PDF 同級。

## 8. 已知限制

| # | 限制 | 影響 |
|---|---|---|
| 1 | multipart 上傳，沒有 byte-level 續傳 | 斷在半路的那一支要整支重來（見 §5） |
| 2 | 腳本不刪任何雲端檔案 | 殘檔要你自己到 Drive 刪，腳本只告訴你 id |
| 3 | `--verify` 只比 `size` 不比 `md5` | 大小對但內容壞掉的情況驗不出來。`md5` 已經存在帳本裡，將來要做深度對帳不必重傳 |
| 4 | 同名資料夾 | Drive 允許同名資料夾。腳本遇到多個同名的會用第一個並印警告 |
| 5 | Google 對單一帳號有每日上傳上限 | 一般說法是 750 GB/日；86 GB 遠低於它，但如果你同一天還在做別的大量上傳就要留意 |
| 6 | `.mp4` 以外一律不上傳 | `.vtt`／`.notes.json`／`.snap_*.jpg` 留在本機——它們小，而且 Service Worker 早就離線快取了（~100MB）。`.mp4.part` 是抓一半的殘檔，副檔名不是 `.mp4`，天然被排除 |

## 10. L3：影片串進 Feb 自己的播放器（2026-09-02）

### 兩種接法，這裡選的是後面那個

| | L2 內嵌預覽 | **L3 直連自家播放器（已實作）** |
|---|---|---|
| 播放器 | Google 的 | **Feb 自己的 `<video>`** |
| 章節時間軸／思考地圖 | ✗ | ✓ |
| 2 倍速（開站預設）／10 秒鍵 | ✗ | ✓ |
| 續播記憶（`feb-playpos-v1`／跨裝置 /sync） | ✗ | ✓ |
| 字幕 | Drive 自己的 | 走 `.vtt`（**但旁掛檔還沒上雲**，見 §12） |
| 實作成本 | 一顆按鈕 | 一條 Service Worker 路由 |

L2 沒有被丟掉——它是 L3 的退路，同一個面板上就有一顆「用 Drive 預覽」。

### 位元組怎麼走

```
<video src="/drive/<fileId>">          ← 同源虛擬路徑，這個檔案並不存在
      ↓ Service Worker 攔下（site/sw.js 的 driveServe）
fetch https://www.googleapis.com/drive/v3/files/<id>?alt=media
      ↓ Authorization: Bearer <存取權杖>，Range 原樣轉手
Google  ──────────────────────────────────→  裝置
```

**Cloudflare 一個請求都不算。**這不是省錢潔癖：Workers 免費方案一天 100,000 個請求
（官方 `workers/platform/limits`：「Accounts on the Workers Free plan have a daily
request limit of 100,000 requests」，而且 `pages/platform/limits` 明講
「Requests to Pages functions count towards your quota for Workers plans」），
而我們的 `_middleware.js` 守全站——**每一個**請求都經過它。一支 900 MB 的影片
光 Range 請求就是幾十到上百個，代理兩堂課就能把整天額度吃光；何況免費方案
記憶體 128 MB、CPU 10 ms，本來就不是搬大檔的地方。

### 為什麼 Content-Range 得自己算

Safari 載影片的第一件事是送 `Range: bytes=0-1` 探路，**沒拿到 206 就整支不播**。
206 一定要帶 `Content-Range: bytes a-b/總長度`——那個「總長度」跟 Google 要不到：

> 2026-09-02 實測 `www.googleapis.com` 的回應標頭：
> `Access-Control-Expose-Headers: Content-Length, Date, Server, Transfer-Encoding,
> X-GUploader-UploadID, X-Google-Trace, date, server, vary`
> —— **沒有 `Content-Range`**，跨來源就讀不到。

所以總長度來自 `drive-map.json` 的 `size` 欄位。這也是為什麼帳本的 `size`
不是備查欄位，而是**播放器的必要條件**：沒有 `size` 那一集就播不了（SW 回 500）。

### 三道自己關上的門

`site/js/14-drive.js` 的 `driveCanPlay()`，任一沒過就當這個功能不存在
（不是降級成半殘）：

1. `data/drive-client.json` 的 `client_id` 是空的 → 關。**預設就是空的**，
   所以在你照 §11 建好 OAuth 用戶端之前，站上一顆相關按鈕都不會出現。
2. 不是雲端模式 → 關。在家有媒體伺服器，直讀硬碟比繞 Google 快得多。
3. Service Worker 沒接管、或接管的是舊版（不認得 `/drive/`）→ 關。
   少了這道，`<video src="/drive/…">` 會直接打到 Cloudflare，
   `_middleware` 驗完章之後找不到這個靜態資產 → 404 → 黑畫面。
   （**第一次造訪時 SW 還沒接管是正常的**，重新整理一次就會亮起來。）

### 權杖住哪裡

記憶體為主、`sessionStorage` 為輔（分頁關掉就沒了）。**永遠不進 `localStorage`，
也永遠不進網址列。** `localStorage` 只放一個 `feb-drive-ok=1` 的布林旗標
（「這台裝置以前成功連過」），那不是憑證。

存取權杖只活一小時，長片一定會撞到過期。SW 收到 401 會清掉手上那張、
回頭跟頁面要一張新的（`drive-need-token` ⇄ `drive-token`），然後**自己重試同一段**，
畫面不中斷。iOS 隨時會回收 Service Worker，醒來記憶體是空的——走的也是同一條路。

> **⚠ 但「靜默續期」在 iPad 上很可能不管用。**
> Google 的 `prompt:''` 走的是隱藏 iframe ＋ Google 的第三方 cookie，
> 而 Safari 預設擋跨站追蹤（ITP）。所以在 iPad 上實際的體感八成是：
> **一小時後要再按一次「連結 Google 雲端硬碟」**。
> 這不是壞掉，站會安靜提示你按一下（不會突然彈視窗搶走畫面）。
> 桌機 Chrome 上靜默續期通常成功，所以這條只影響 iPad。

### 驗過什麼（2026-09-02，真 Chrome 151 + Playwright）

拿 `site/sw.js` 本尊（只把上游主機名換成本機的假 Google，**跨來源**、
而且刻意不 expose `Content-Range`，姿態與 googleapis.com 一致）跑了 11 項：

| 項 | 結果 |
|---|---|
| CORS 預檢（`Authorization` + `Range`） | ✓ 通過，`Access-Control-Max-Age: 3600` |
| `Range: bytes=0-1`（Safari 的開場探測） | ✓ 206／2 bytes／`Content-Range: bytes 0-1/11233368` |
| 開放式 `bytes=N-` 夾到 16 MiB | ✓ 短回的 206，播放器自己接著要下一段 |
| 尾段 `bytes=<size-100>-` | ✓ 206 |
| 超出範圍 | ✓ 416＋`Content-Range: bytes */size` |
| 不在帳本裡的 id | ✓ 404 |
| 不帶 Range | ✓ 200＋完整 `Content-Length` |
| `<video>` 讀 metadata（靜音、不播放） | ✓ duration 正確 |
| `<video>` 拖曳快轉 | ✓ `seeked` 觸發，位置正確 |
| **影片有沒有進任何快取** | ✓ **0 個**（86 GB 永不進快取的鐵則沒破） |
| 權杖過期 → 換票重試 | ✓ SW 要了 1 次新權杖，重試後 206 |

把 chunk 縮到 1 MiB 再跑一次，metadata 與快轉**照樣過**——
也就是「一支影片切成上百個短 206」這個真實情境是成立的。

### iOS Safari 的風險，講白話

這條路歷史上最脆的一段就是 iOS。老問題是
[WebKit 184447](https://bugs.webkit.org/show_bug.cgi?id=184447)
「mp4 video element broken with service worker」（2019-11-05 RESOLVED FIXED）：
媒體請求以 no-cors 送出，標頭過濾把 `Range` 拔掉，SW 根本不知道要拿哪一段。
2018 年那一票災情（Jeremy Keith 的 adactio 那篇、Phil Nash 那篇）**全部是同一種**：
SW 攔了影片卻回一個完整的 200，Safari 收到不是 206 就罷工。

我們這支不犯那個錯——**只回 206、而且一定帶 `Content-Range`**，
而且播放器的 `<video>` 本來就帶 `crossorigin="anonymous"`，
請求模式是 cors 不是 no-cors，正好避開當年那條標頭過濾。

**但這台電腦上驗不了 iOS Safari。** 所以有一支探針，30 秒可以自己驗完：

> iPad 用 Safari 開 **`site/probe/drive-range-probe.html`**
> （本機模式：`https://<電腦IP>:8796/site/probe/drive-range-probe.html`，
> 先按「用媒體伺服器的第一支影片」再按「開始測試」）
>
> 🔇 這一頁**不會發出任何聲音**：`<video>` 一律靜音、`preload="metadata"`，
> 全程不呼叫 `play()`，只讀 metadata 與跳一次時間軸。
>
> 看兩件事：
> 1. 最下面那張表，`dest=video` 那幾列的 `range` 欄**有沒有值**。
>    是「—」就代表這台裝置把 Range 從 SW 眼前拔掉了，L3 不成立。
> 2. 上面那句判定。綠的就是可以。
>
> 判定是紅的 → 不必改任何設定，**L3 會自己退到 L2**：
> `<video>` 一報錯就自動切成 Drive 內嵌預覽（`10-player.js` 的 `v.onerror`）。
> 你會少掉 2 倍速與續播記憶，但看得成課。
>
> 驗完可以按「移除這支探針 SW」，它跟正式的 Service Worker 是分開的兩個 scope，
> 留著或移掉都不影響離線教材快取。

## 11. 你要去 Google Cloud Console 點什麼（只有你能做）

腳本不碰、我也不碰：建立帳號、輸入密碼、按下同意，這三件事一律由你本人操作。
下面是逐步的點擊路徑。**全部做完之前，站上不會出現任何 Drive 相關按鈕。**

### 11.1 選專案

1. 開 <https://console.cloud.google.com/>，用**上傳影片的那個 Google 帳號**登入
   （`gws drive about get` 顯示的那一個）。
2. 頁面最上方藍色列的**專案下拉選單** → 挑一個既有專案，
   或按「新增專案」，名字取 `Feb`（其他欄位留預設）→ 建立 → 再回下拉選單選它。
   *專案只是容器，跟 Drive 裡的檔案無關，開一個新的最乾淨。*

### 11.2 啟用 Drive API

3. 左上角 **☰ 選單 → API 和服務 → 已啟用的 API 和服務 → ＋啟用 API 和服務**。
4. 搜尋 `Google Drive API` → 點進去 → **啟用**。

### 11.3 設定「Google 驗證平台」（＝以前的 OAuth 同意畫面）

5. **☰ 選單 → Google 驗證平台（Google Auth Platform）**。
   第一次進來會要你先做基本設定：
   - **應用程式名稱**：`Feb`
   - **使用者支援電子郵件**：你的信箱
   - **目標對象（Audience）**：選 **外部（External）**
     *個人 Gmail 帳號只有這個選項；「內部」是 Google Workspace 組織才有。*
   - **聯絡資訊**：你的信箱 → 建立。
6. 左側 **目標對象（Audience）**：
   - **發布狀態**維持 **測試中（Testing）**。**不要按「發布應用程式」。**
   - 往下找到 **測試使用者 → ＋Add users**，把**你自己的 Gmail** 加進去 → 儲存。
     漏掉這一步，授權時會被擋在 `access_denied`。
7. 左側 **資料存取（Data Access）→ 新增或移除範圍**：
   - 在下方的「手動新增範圍」貼上
     `https://www.googleapis.com/auth/drive.readonly`
     → 新增至表格 → **更新** → **儲存**。
   - 它會被歸類到「受限範圍（Restricted）」並顯示需要驗證的提示。
     **測試中狀態不需要通過 Google 驗證，也不需要付費的 CASA 資安評估**，
     只是授權時會多一個「Google 尚未驗證這個應用程式」的畫面（見 11.5）。

### 11.4 建立 Web OAuth 用戶端

8. 左側 **用戶端（Clients）→ ＋建立用戶端（Create Client）**。
9. **應用程式類型** 選 **網頁應用程式（Web application）**。
10. **名稱**：`Feb 網頁`。
11. **已授權的 JavaScript 來源（Authorized JavaScript origins）→ 新增 URI**，
    加**兩條**（一條一列，結尾不要斜線）：

    ```
    https://feb-6ah.pages.dev
    http://localhost:8795
    ```

    *官方規則：JavaScript 來源必須是 https，**localhost 是唯一例外**
    （`support.google.com/googleapi/answer/6158849`）。所以家裡那台
    `https://192.168.x.x:8796` 自簽憑證的網址**填不進去也用不了**——
    L3 本來就只在雲端模式開（見 §10 第 2 道門），不衝突。*
12. **已授權的重新導向 URI**：**留空**。走的是瀏覽器端權杖模式，沒有伺服器端回呼。
13. **建立**。跳出來的視窗裡有一串
    `123456789012-xxxxxxxxxxxxxxxxxxxxxxxxxxxx.apps.googleusercontent.com`
    —— 那就是 client_id，**複製它**。

### 11.5 貼進 Feb

14. 在專案根目錄跑這一行，把剛剛複製的那一串貼在後面：

    ```
    python scripts/set-drive-client.py 123456789012-xxxxxxxxxxxx.apps.googleusercontent.com
    ```

    腳本會擋掉兩種貼錯：貼成 **client secret**（`GOCSPX-` 開頭）、
    或貼成專案編號之類格式不符的東西。這兩種貼進去都**不會報錯**，
    只會在瀏覽器裡靜靜失敗——而那個症狀跟「還沒設定」長得一模一樣，
    是這整段最貴的一種錯。手改 JSON 也可以，但少一個引號、
    或編輯器存成 BIG5，症狀同樣是「按鈕整個不出現」。

    **這個檔不是機密**（client_id 本來就會出現在網頁原始碼裡），
    但它跟其他教材一樣站在 `_middleware.js` 後面，匿名讀不到。
    真正的機密是 client **secret**——網頁應用程式的權杖模式**用不到它**，
    所以不要把它貼進任何檔案。
15. 重新部署——在專案根目錄跑：

    ```
    npm run deploy
    ```

    （它會先 build 再 deploy。刻意**不用** `npx wrangler@4.127.1`：釘版本會強制
    去 registry 重抓，就是先前撞 `EBUSY` 卡住的那條路。npm scripts 裡的
    `wrangler` 直接解析到專案內的 `node_modules/.bin`，不出網。）
    （`data/*.json` 深度 1 本來就在 `build-dist.mjs` 的 `ALLOW` 裡，不必改白名單。）
16. iPad 上打開 `https://feb-6ah.pages.dev`，**重新整理一次**讓新的 Service Worker
    接管，點任何一集 → 隨播面板會多出「連結 Google 雲端硬碟」。
    按下去 → Google 授權視窗 → 「**Google 尚未驗證這個應用程式**」那一頁按
    **進階 → 前往 Feb（不安全）** → 勾選 Drive 唯讀權限 → 繼續。
    *那句「不安全」是給不認識開發者的人看的警語。這個應用程式就是你自己建的，
    只有你一個測試使用者，而且只要唯讀權限。*

### 11.6 之後

- 存取權杖只活一小時。**2026-09-13 起（ADR-0011）權杖由後端以服務帳戶簽發、到期前五分鐘自動換一張**，
  不再有 Google 視窗；只有在後端 secret `GOOGLE_SA_KEY` 還沒設好時，才退回舊的 GIS 靜默續期
  （`prompt:''`）——那條在 iPad 上幾乎必失敗，每小時要按一次「重新連結 Google」。
- 換裝置、清掉瀏覽器資料、或很久沒用，會再要求按一次「連結」。
- 要收回權限：<https://myaccount.google.com/permissions> 找到 `Feb` → 移除存取權。
