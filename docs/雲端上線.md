## 1. R2 拿掉了：教材改成部署裡的靜態資產

你的裁定是**完全不開通 R2**（R2 要訂閱、可能要綁付款方式＝多一個計費面）。
所以整條 R2 路徑從程式碼裡刪乾淨了，不是「留著先不用」：

| 刪掉的東西 | 原本做什麼 |
|---|---|
| `wrangler.jsonc` 的 `r2_buckets` | 綁 `ARCHIVE` → `feb-archive` |
| `functions/api/data/[[path]].js` | R2 的唯一出口 `/api/data/**` |
| `functions/_lib/data-path.mjs` | 執行期的路徑白名單 |
| `scripts/cloud/r2-upload.mjs` | 上傳教材到桶子 |
| `functions/_lib/private-pages.mjs` | 只守 `/api/*` 時代用來補守兩張地圖的例外清單 |

教材（考古題 PDF、招生簡章、章節分析、筆記快照）改成**隨部署上傳的 Pages 靜態資產**，
網址就是最單純的 `/data/**`。撐住這個決定的是實測數字對上官方上限：

| | 我們 | Pages 免費方案 |
|---|---|---|
| 檔案數 | 351 | 20,000 |
| 單檔最大 | 15.1 MiB | 25 MiB |
| 總大小 | 177.8 MiB | 頻寬／請求數不限 |

（官方 `pages/platform/limits/`：「Cloudflare Pages sites can contain up to 20,000 files
on the Free plan」、「The maximum file size for a single Cloudflare Pages site asset is 25 MiB」。）

### 那安全性靠什麼

靠 `functions/_middleware.js` **守全站**。這是整個決定成立的唯一前提：
靜態資產本來會繞過驗章直接公開，所以「教材當靜態資產」與「middleware 守全站」
是同一個決定的兩半，拆開就漏。

可行的依據是官方文件（`workers/static-assets/migration-guides/migrate-from-pages/`）：
「Pages would default to serving your Pages Functions ahead of static assets」——
Pages 預設先跑 Functions 再送靜態資產。`dist/_routes.json`（`include: ["/*"]`、
`exclude: []`）再把這件事寫死，不靠預設值。

從 Phase D 到 Phase E 的差別：Phase D 只守 `/api/*` 外加一份 `PRIVATE_PAGES` 例外清單
（`/la-map`、`/me-map`）；Phase E **沒有例外清單**，連 `index.html`、CSS、字型都要驗過章。
少一條要維護的例外，就少一個「哪天加了新頁面忘記加進清單」的失效模式。

### 代價（要記得）

教材與程式碼綁在同一個部署裡：**改一份 PDF 就要重跑一次建置＋部署**。
好消息是 wrangler 會跳過已經上傳過的檔案（實測第二次部署：
`Uploaded 0 files (351 already uploaded) (0.51 sec)`），所以只有第一次是 178 MB／約 4 分鐘。

## 2. 建置與部署（現在的正確指令）

```bash
cd "C:/Users/User/Desktop/claude/feb2"

# ① 先盤點，不寫任何東西
node scripts/cloud/build-dist.mjs --dry-run

# ② 真的組出 dist/（冪等：每次都先清空重來）
node scripts/cloud/build-dist.mjs

# ③ 部署 dist/，不是 site/
npx wrangler@4.127.1 pages deploy dist --project-name feb --branch main
```

> **注意部署的是 `dist` 不是 `site`。**部署 `site` 會少掉全部教材，
> 而且不會有 `_routes.json`——那份檔案是「每個請求都先跑 Functions」的地基。

`build-dist.mjs` 有兩條**硬拒絕**（中止建置，不是警告）：

1. 單檔超過 25 MiB（Pages 上限，硬闖只會傳到一半才失敗）
2. 任何影片副檔名（86 GB 課程影片永不上雲；白名單本來就放不進去，這是第二道保險）

它也**不跟隨 symlink／junction**——`media/` 指向外接硬碟，跟過去會把 86 GB 拉進部署。

成功時會印出兩個網址：正式的 `https://feb-6ah.pages.dev`，
以及這一次部署專屬的 `https://<8 位雜湊>.feb-6ah.pages.dev`。
**兩種都會通**，所以第 3 步的 Access 應用要把兩種都蓋住。

## 3.〔只有你能做〕建立 Zero Trust Access 應用

Access 才是真正的門。現在的 403 是「沒設定所以誰都不給」，
設完之後才變成「是你本人所以給」。

### (a) 建立應用

1. 開 **Cloudflare One（Zero Trust）**：https://one.dash.cloudflare.com/
   - 第一次進去會要你**取一個 team name**（例如 `feb`）。這個名字決定你的團隊網域
     `https://<team-name>.cloudflareaccess.com`，**第 4 步的 `ACCESS_TEAM_DOMAIN` 就是它**，
     取好之後很難改，想清楚再按
   - 方案選 **Free**（50 人以內免費）
2. 左邊選 **Access controls** > **Applications**
3. 按 **Create new application**（舊版介面寫 **Add an application**）
4. 類型選 **Self-hosted**（自架應用）
5. **Application name** 填 `feb`
6. **Application domain／Public hostname** 加**兩筆**：

   | Subdomain | Domain |
   |---|---|
   | `feb-6ah` | `pages.dev` |
   | `*.feb-6ah` | `pages.dev` |

   第二筆（萬用字元）是必要的：**每一次部署都會多一個
   `<雜湊>.feb-6ah.pages.dev` 網址**（現在已經有 `f92b07c6`、`f2e8bd72`、`a4096cc3` 三個），
   只蓋正式網址的話那些別名沒人看門。
   如果介面不接受萬用字元，就退而求其次只加第一筆——那些別名仍然被
   `_middleware.js` 擋著（實測全部 403），但那是第二層，不是 Access。

7. **Session duration** 建議 `1 month`（iPad 上不會三天兩頭要你重登）

### (b) 加一條 Allow 政策

在同一個建立流程的 **Policies** 步驟（或事後 **Edit** > **Policies** > **Create new policy**）：

| 欄位 | 值 |
|---|---|
| Policy name | `feb 的人` |
| Action | **Allow** |
| Rule type | **Include** |
| Selector | **Emails** |
| Value | `you@example.com` |

要給朋友時，按 **＋ Add include**（或 **Or**）再加一列，同樣選 **Emails**，填他的信箱。
**還沒要給人的時候就只留你自己那一列**——不要為了「之後方便」先放
`Emails ending in @gmail.com` 這種規則，那等於把整個 gmail 開放給全世界。

登入方式（Login methods）保留預設的 **One-time PIN** 就夠：
輸入信箱、收一封驗證碼信、貼回去。不必註冊任何帳號、不必設密碼。

> **沒有政策的應用會拒絕所有人**（官方：「An application with no policy denies every
> request」）。所以就算你只做到 (a) 沒做 (b)，也是安全的，只是連你自己都進不去。

### (c) 抄下 AUD

1. **Access controls** > **Applications** > 點 `feb`
2. **Overview**（或 **Application Configuration**）分頁
3. 找 **Application Audience (AUD) Tag**，是一串 64 位十六進位字，按複製

這串就是第 4 步的 `ACCESS_AUD`。
它的作用：少了它，**同一個團隊底下任何一個 Access 應用簽出來的票**都能開 Feb。

## 4. 設 Pages 環境變數

**三個變數，缺任何一個全站就繼續 403。**

| 變數 | 值 | 哪裡來 |
|---|---|---|
| `ACCESS_AUD` | 64 位十六進位 | 第 3(c) 步的 AUD Tag |
| `ACCESS_TEAM_DOMAIN` | `https://<team-name>.cloudflareaccess.com` | 第 3(a) 步取的 team name；**必須 https**（公鑰走明文取得等於把整套身分交給中間人） |
| `FEB_OWNER` | `you@example.com` | 你自己。只有這個身分能寫進度，其他人唯讀 |

### 指令（推薦）

每一條會互動式問你值，貼上按 Enter：

```bash
cd "C:/Users/User/Desktop/claude/feb2"
npx wrangler@4.127.1 pages secret put ACCESS_AUD --project-name feb
npx wrangler@4.127.1 pages secret put ACCESS_TEAM_DOMAIN --project-name feb
npx wrangler@4.127.1 pages secret put FEB_OWNER --project-name feb

# 確認三個都在（只列名稱，不會印出值）
npx wrangler@4.127.1 pages secret list --project-name feb
```

### 為什麼一定要用 secret，不要用一般的 variable

`wrangler.jsonc` 一旦存在，它就是 Pages 專案設定的**唯一真相**——官方文件
（`pages/functions/wrangler-configuration/` 的 Source of truth 一節）明講 Dashboard 上
看得到但改不動同樣的欄位。`wrangler.jsonc` 裡沒有 `vars`，所以在 Dashboard 上手動加的
**一般變數可能在下次部署被抹掉**；**secret 不會**（官方：「Wrangler will not delete your
secrets ... unless you run wrangler secret delete」）。

要用 Dashboard 設也可以：**Workers & Pages** > `feb` > **Settings** >
**Variables and Secrets** > **Add**，填好之後**勾 Encrypt**（＝secret）再 Save。
如果你之後會用預覽分支，**Production 與 Preview 兩個環境都要各設一份**。


```
Content-Type: application/json; charset=utf-8
Cache-Control: private, no-store
```

- **Access**（第 3 步）擋在邊緣：連登入頁都是 Cloudflare 發的，請求根本到不了我們的程式碼
- **`_middleware.js`** 是 repo 裡的後盾：Dashboard 上的設定還沒做、
  或日後那個 Access 應用被誰刪掉、環境變數被清掉時，全站立刻回到「誰都不給」

兩層都在，才叫做「設定錯不會外洩」。

## 7. 之後怎麼加／移除朋友

**加人**（他不需要註冊任何東西，只要收得到信）：

1. https://one.dash.cloudflare.com/ > **Access controls** > **Applications** > `feb` > **Edit**
2. **Policies** 分頁 > 點那條 Allow 政策
3. **Include** 底下按 **＋ Add include**，Selector 選 **Emails**，Value 填他的信箱
4. **Save**

生效是即時的，**不必重新部署**。他登入後拿到的是 `role: "guest"`：
看得到跟你一模一樣的看板與教材，但 `POST /api/progress` 會被回 403，
他的進度只留在他自己裝置的 localStorage，一個位元組都不會寫進你的 D1。

**移除**：同一個地方把他那一列 include 刪掉、Save。
他手上那張票最長活到 session duration 到期（你設的 1 個月）。
要**立刻**踢掉，就到 **Access controls** > **Users**（或該應用的 **Logs**）找到他，
按 **Revoke session**。

## 9. 費用：免費額度天花板，以及「會失敗，不會計費」

**全部落在免費額度內，而且都在 Workers Free 方案上——超過額度的行為是「回錯誤」，
不是「開始收錢」。**這是不開 R2 之後最大的好處：帳號上沒有任何一個會計費的產品。

| 服務 | 免費上限 | 我們的用量 | 超過會怎樣 |
|---|---|---|---|

| **Zero Trust Access** | 50 位使用者 | 1–2 位 | — |

兩件要放在心上的：

1. **D1 的免費每日額度從 2026-09-01 起是硬限制**——官方 changelog
   `2026-09-01-d1-free-tier-limit-enforcement` 明講：「D1 queries on the Workers Free plan
   will fail when an account exceeds the daily row read or row write limits ...
   return errors until the limit resets at midnight UTC. **Stored data is not affected.**」
   哪天 `/api/progress` 開始回「Your account has exceeded D1's free tier daily row read
   limit」，就是這件事：資料沒有壞，等午夜重置或降低用量即可。
2. **Workers Free 每日 10 萬次請求**，超過回 Error 1027。以 Feb 的用量差三個數量級。
   注意**每一個靜態檔案也算一次 Functions 請求**（全站都經過 middleware），
   所以「開一次站」大概是幾十次請求，不是一次。

**沒有任何一個服務會因為超量而自動扣款**，因為帳號上沒有付費方案、沒有 R2 訂閱。
超過就是壞掉，壞掉就是等重置——這是刻意選的失效模式。
