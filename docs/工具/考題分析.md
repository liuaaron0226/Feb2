# 考題分析（`scripts/run_notebooklm_analysis.py`）

把各校十年考古題丟給 Google NotebookLM 分析，得到「哪個章節、哪一年、考了第幾題」的熱度表，
加上必考重點和命題趨勢。結果存成 `data/analysis/*.json`，網站的「考題分析」區
（熱度表、十年考點）直接讀這些檔案。

分析在 NotebookLM 那一端完成，**不耗 Claude／OpenAI 的 token**，也不需要任何 API 金鑰。

---

## 前後兩支腳本

```
scripts/fetch_exams.py              抓各校電機控制組 106–115 學年考古題 PDF
  │                                 → data/exams/<學校>/<科目>/<學年>.pdf
  │                                 → data/exam-index.json（網站的考古題連結）
  ▼
scripts/run_notebooklm_analysis.py  每個「學校×科目」建一個 NotebookLM 筆記本
                                    → 上傳該組十年 PDF → 要求輸出嚴格 JSON
                                    → data/analysis/<key>.json ＋ index.json
```

`fetch_exams.py` 只用標準函式庫。各校網站的結構是 2026-07 的探測結果，
學校改版時要調整對應的 `discover_*` 函式。

## 前置

| 項目 | 說明 |
|---|---|
| 套件 | `pip install notebooklm-py`（非官方 NotebookLM 函式庫） |
| 登入 | `python -m notebooklm login`，一次性 Google 登入。憑證由 notebooklm-py 存在使用者目錄，不在 repo 裡 |
| 考卷 | `data/exams/` 裡要有 PDF（先跑 `fetch_exams.py`）；考卷不進 repo |

程式開跑前會先用 `notebooklm auth check` 確認登入狀態，沒登入會直接提示並結束。

## 用法

平常雙擊專案根目錄的 bat：

| 入口 | 做什麼 |
|---|---|
| `run_analysis.bat` | 跑一輪分析：`run_notebooklm_analysis.py` |
| `run_redo.bat` | 章節分類改過之後重問一輪：加上 `--redo` |

也可以直接下指令：

```
python scripts/run_notebooklm_analysis.py                  # 全部分析組
python scripts/run_notebooklm_analysis.py --only ntu-control  # 只跑一組
python scripts/run_notebooklm_analysis.py --dry-run        # 只列每組會用幾份 PDF
python scripts/run_notebooklm_analysis.py --redo           # 沿用既有筆記本，用新章節重問
```

## 每一組做什麼

分析組定義在程式裡的 `GROUPS`：代號（如 `ntu-control`）、NotebookLM 筆記本標題、
考卷資料夾、學校、科目、章節分類清單、附加指示。
章節分類清單是程式開頭的 `CTRL`、`ELEC`、`SIGS`、`LA`、`MATH7` 等常數。

1. **建筆記本**：還沒有就建一個，id 記進 `_state.json`
2. **上傳考卷**：逐份上傳並記錄，全部上完後等 NotebookLM 處理完成（每 30 秒查一次）
3. **提問**：要求它逐份考卷把每個大題歸進指定章節，統計「章節×學年度」出現次數與題號，
   整理 3~6 條必考重點和兩三句命題趨勢，而且只能輸出 JSON
4. **存檔**：補上學校、科目、日期、筆記本 id，寫成 `data/analysis/<key>.json`，
   再重建 `index.json`

中山大學的控制系統和工數乙來自同一份全系合集，所以兩組共用一個筆記本，
必須先完成 `nsysu-control`。

## 中斷與重跑

進度存在 `data/analysis/_state.json`：每組的筆記本 id、已上傳的 PDF、來源是否就緒、是否完成。
**隨時可以 Ctrl+C**，重跑時會跳過已完成的組和已上傳的 PDF。

- 提問失敗會等 2 分鐘再試一次，兩次的原始輸出存成 `_raw_<key>_<次數>.txt`
- 某組失敗不影響其他組，之後用 `--only <key>` 單獨補跑
- 每組的完整提問內容存成 `_prompt_<key>.txt`，方便核對問了什麼

## 輸出格式

```jsonc
{
  "years": [106, 107, "…"],
  "chapters": [
    { "name": "穩定度(Routh-Hurwitz)",
      "years": { "106": 2, "107": 1 },        // 該學年這章出了幾個大題
      "qs":    { "106": [2, 5], "107": [3] } } // 對應的大題題號
  ],
  "mustKnow": ["主題：一句話說明常見考法"],
  "trend": "近年命題趨勢…",
  "school": "台大", "subject": "控制系統", "updated": "2026-08-21",
  "notebook": "<NotebookLM 筆記本 id>", "engine": "NotebookLM"
}
```

## 相關工具

**NotebookLM 筆記迴流**（`scripts/nblm_pull.py`）：這支和考題分析無關。它把五科筆記本裡
你自己寫的筆記抓回 `data/nblm/`，給網站離線閱讀，前置同樣是 `python -m notebooklm login`。
觸發方式（開站自動、週日排程）見 [`docs/自動化.md`](../自動化.md)。
`data/nblm/` 屬於個人筆記，不進公開 repo。
