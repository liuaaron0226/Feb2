## 一、開站自動迴流 NotebookLM 筆記

### 怎麼運作

打開或重新整理網站 → 首次繪製完成後，網頁**射後不理**地打一發
`GET /nblm/refresh` → 伺服器把 `nblm_pull.py` 丟到背景跑 → 立刻回應。
網頁從不等待，失敗全部安靜吞掉，首屏一毫秒都不會被拖慢。

如果伺服器回報「真的去拉了」，網頁會在 **45 秒後**回讀一次
`data/nblm/*.json`；內容真的變了、而且站 03 正在畫面上，才重繪那一段。
所以**同一次開站就吃得到新筆記**，不必再手動重整第二次。

### 端點規格

`GET /nblm/refresh`（`serve_media.py`，認證與其他端點同一套；本機一律放行）

| 情況 | 回應 |
|---|---|
| 距離上次拉取 < 節流時數 | `{"skipped":true,"last":"2026-09-01 23:05:19","age_s":102,"throttle_h":6.0,"next_in_s":21497}` |
| 真的啟動了 | `{"started":true,"pid":75700,"log":"…\nblm_pull.log","throttle_h":6.0}` |
| 找不到 `scripts/nblm_pull.py` | `{"skipped":true,"reason":"no-script","script":"…"}` |
| 啟動失敗 | `{"error":"…"}`（戳記會退回，不會白白擋住六小時） |

實測回應時間：**18～20 毫秒**（不論 started 或 skipped）。

### 檔案位置（全絕對路徑）

| 東西 | 路徑 |
|---|---|
| 端點程式 | `C:\Users\User\Desktop\claude\istudy-private-backup\tools\serve_media.py` |
| 網頁那一半 | `C:\Users\User\Desktop\claude\feb2\site\js\11-boot.js`（`nblmAutoRefresh` / `nblmReload`） |
| 實際拉取腳本 | `C:\Users\User\Desktop\claude\feb2\scripts\nblm_pull.py` |
| 節流戳記 | `C:\Users\User\Desktop\claude\istudy-private-backup\data\nblm-pull.stamp` |
| 拉取日誌 | `C:\Users\User\Desktop\claude\istudy-private-backup\reports\nblm_pull.log` |
| 落地的筆記 | `C:\Users\User\Desktop\claude\feb2\data\nblm\*.json` |

### 節流：預設 6 小時

一天重整幾十次也只會真的拉一次。要改就設環境變數
**`FEB_NBLM_THROTTLE_H`**（單位：小時）：

- `FEB_NBLM_THROTTLE_H=0` → 每次開站都拉（很吵，只在除錯時用）
- `FEB_NBLM_THROTTLE_H=24` → 一天最多一次
- 設成壞值（打錯字）→ 自動退回預設 6，伺服器不會因此起不來

設在哪：開機自啟的 vbs 裡（與 `FEB_HUB` 同一個地方），或 `start_feb_dev.bat`。
**改完要重啟伺服器才生效。**

想立刻再拉一次而不改設定：把戳記檔刪掉即可
（`C:\Users\User\Desktop\claude\istudy-private-backup\data\nblm-pull.stamp`）。

### 怎麼停用

由輕到重，三選一：

1. **只是想拉稀一點** → 設 `FEB_NBLM_THROTTLE_H=168`（一週一次）。
2. **完全不要開站自動拉** → 編輯
   `C:\Users\User\Desktop\claude\feb2\site\js\11-boot.js`，
   把最底下那段 `if(SAME_ORIGIN_MEDIA && …) addEventListener('load', …)` 註解掉。
   端點還在，但沒人會打它。
3. **連端點也拿掉** → 編輯 `serve_media.py`，刪掉 `do_GET` 裡
   `if clean == "/nblm/refresh":` 那兩行。

### 只在「媒體伺服器供應網站」時才會打

判斷式是 `SAME_ORIGIN_MEDIA`（`site/js/05-media.js`）：連接埠是
**8795 / 8796 / 8797 / 8798** 才算。從 `start_feb.bat` 的 **8643**
（`python -m http.server`）開站時**完全不會打**——那邊沒有這個端點，
打了只會在 console 留一排 404。已實測確認。

### 什麼時候開始生效

`serve_media.py` 是**服役中的行程已經載入的程式**，改檔案不會影響正在跑的那一個。
**下次重開機（開機自啟）或手動重啟 8795/8796 之後**，開站自動迴流才會真的動起來。
在那之前網頁照打，只是拿到 404，安靜跳過，什麼都不會壞。

## 二、週日教材保鮮（排程工作）

### 排程規格

| 項目 | 值 |
|---|---|
| 工作名稱 | `Feb 週日教材保鮮` |
| 排程 | 每週日 10:00（`/SC WEEKLY /D SUN /ST 10:00`） |
| 權限 | `/RL LIMITED`（一般權限，不提權） |
| 登入模式 | Interactive only —— **只有你登入時才會跑** |
| 喚醒電腦 | **否**（`WakeToRun` 未設定＝false，不會半夜自己醒來） |
| 動作 | `"C:\Users\User\Desktop\claude\feb2\scripts\週日保鮮.bat"` |
| 逾時 | 72 小時 |
| 電池 | 靠電池時不啟動、中途改吃電池會停（Windows 預設） |

### 每個星期日它會做什麼

1. **提醒**：視窗跳出來，寫著「今天是星期日 —— 記得跑一趟偉文」，
   叫你把新錄的課程與新講義帶回來放進 `F:\istudy-backup`。
   接著是 **15 秒倒數**（不是 pause，不用按任何鍵，看得完就自己開始）。
2. **[1/3] 字幕**：`feb2\tools\make_subs.py`
   —— whisper／GPU，只做還沒有 `.vtt` 的影片。
3. **[2/3] 思考地圖**：`feb2\tools\make_notes.py`
   —— `claude -p`，只做還沒有 `.notes.json` 的影片；順便套勘誤、抽板書快照、
   重建全文搜尋索引。
4. **[3/3] 筆記迴流**：`feb2\scripts\nblm_pull.py` —— 把 NotebookLM 五科筆記抓回本地。
5. 全部完成後印一行「完成」，視窗 **30 秒後自動關閉**。

**今天剛從偉文拿回來的東西，這一輪不會處理到**（它跑在你出門之前）。
下週日會自己補上；等不及就手動雙擊
`C:\Users\User\Desktop\claude\feb2\scripts\週日保鮮.bat` 再跑一次，行為完全一樣。

**外接硬碟沒接**（拔去接 iPad 了）時，[1/3] 與 [2/3] 會整段跳過並在日誌寫明原因，
[3/3] 照跑（筆記迴流跟硬碟無關）。

### 日誌

`C:\Users\User\Desktop\claude\feb2\reports\週日保鮮.log`

每個階段都有時間戳（含星期），三支 python 的完整輸出也都導進同一份檔案。
想邊跑邊看，另開一個 PowerShell 視窗：

```powershell
Get-Content -Wait -Tail 30 -Encoding UTF8 "C:\Users\User\Desktop\claude\feb2\reports\週日保鮮.log"
```

### 怎麼停用

```
schtasks /Delete /TN "Feb 週日教材保鮮" /F
```

只想暫停一陣子（保留設定）：

```
schtasks /Change /TN "Feb 週日教材保鮮" /DISABLE
schtasks /Change /TN "Feb 週日教材保鮮" /ENABLE
```

想改時間（例如改成下午三點）：

```
schtasks /Change /TN "Feb 週日教材保鮮" /ST 15:00
```

查目前設定：

```
schtasks /Query /TN "Feb 週日教材保鮮" /V /FO LIST
```

手動觸發一次（跟星期日自己跑起來一模一樣）：

```
schtasks /Run /TN "Feb 週日教材保鮮"
```

跑到一半想停：

```
schtasks /End /TN "Feb 週日教材保鮮"
```

> 這些指令都要在 **cmd** 裡打，而且視窗要先 `chcp 65001`，
> 不然工作名稱裡的中文會對不上。最保險是直接開「工作排程器」圖形介面操作。

## 踩過的坑（別再踩）

### 1. `.bat` 的 `rem` 註解行不能寫中文

原本在 `週日保鮮.bat` 的註解裡「好心」寫了停用排程的指令當說明：

```
rem  停掉排程：  schtasks /Delete /TN "Feb 週日教材保鮮" /F
```

**cmd 把它執行了。** 中文出現在 `rem` 後面時，cmd 會把同一行的後半段
當成真正的指令跑掉——於是這個排程工作**每跑一次就把自己刪掉一次**，
症狀是「明明建立成功、跑完就查不到了」，找了很久。

規則：**`rem` 行一律只寫 ASCII**；所有中文只放在 `echo` 或
`call :log "…"` 的引號裡（那些都實測正常）。

### 2. 不要用 PowerShell 的 `Set-ScheduledTask` 去改 schtasks 建的工作

一開始想加 `StartWhenAvailable`（錯過的話開機後補跑），
用 `Set-ScheduledTask` 改下去之後工作就消失了，一度以為是它的錯。
後來證明真兇是上面那個 `rem`。但既然 `schtasks /Create` 一條指令就夠，
**就不要再讓第二個工具去碰同一個註冊**，少一個變數。

代價：如果星期日 10:00 電腦是關的，這一次就跳過，不會補跑。
在意的話請到「工作排程器」圖形介面勾「錯過排程時間後，盡快啟動工作」。

### 3. `補字幕與筆記.bat` 不能直接被排程叫

那支結尾有 `pause >nul`，排程叫起來會**永遠卡在那裡等你按鍵**。
所以 `週日保鮮.bat` 不呼叫它，而是直接叫同樣的兩支 python
（`make_subs.py`、`make_notes.py`），順序與參數完全一致。
`補字幕與筆記.bat` 保留原樣，給手動雙擊用。
