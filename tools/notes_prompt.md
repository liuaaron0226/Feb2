## 輸出 JSON（鍵名照抄，不要多不要少）

{
  "fixes": [["誤寫","正確"]],
  "chapters": [{"t":0,"title":"開場與本集導覽"}],
  "keys": [{"a":1234,"b":1450,"why":"為何是重點(≤20字)"}],
  "snaps": [{"t":4021,"cap":"圖說(≤24字)"}],
  "map": {
    "tldr": ["本集重點一句話"],
    "flow": "graph TD ...",
    "concepts": [{"name":"概念名","mermaid":"","svg":"","md":"","sup":"","trap":"",
                  "formulas":[{"tex":"I=I_S(e^{V/nV_T}-1)","name":"二極體方程式","when":"何時能用(≤14字)"}],
                  "compare":{"title":"比較什麼","cols":["軸","A","B"],"rows":[["判準","...","..."]]}}],
    "examples": [{"t":4021,"tag":"考點標籤","trigger":"題目出現什麼就用這招(≤18字)","md":"步驟","trap":"陷阱","snap":4021}],
    "playbook": [{"trigger":"題目給了什麼(≤16字)","method":"用哪招(≤16字)"}],
    "pitfalls": [{"wrong":"錯誤寫法/常見誤解","right":"正確寫法","why":"為什麼(≤20字)"}]
  }
}

### fixes / chapters / snaps
- fixes：只收確定的術語辨識錯字，字面替換，長度≥2，不可是日常常用詞（教訓：「反正」是口頭禪，別收）。沒把握就空陣列。
- chapters：6~15 段涵蓋整堂課，t 嚴格遞增、第一段 t=0，title ≤12 字用內容命名。
- snaps：板書最完整的瞬間（例題講完、換下一題之前），至多 6 個。

### keys — 重點時段（數量跟片長連動，不要湊數）
**段數 ≈ 片長分鐘數 ÷ 9**。這是估算不是配額，該堂密就多標、鬆就少標，但**不准每堂都收在同一個數字**。整堂被標為重點的時間合計約 **35%~55%**。
- 要標：定義／定理／公式的正式陳述與「為什麼長這樣」、解題方法的推導與步驟總結、例題中**做判斷**的那幾句、老師明說「這個會考／一定要記／最多人錯」、老師回頭重講的內容。
- 不要標：班務閒聊、唸數字代入計算、同一件事的第二三次重複、抄板書空檔。
- a/b 取自逐字稿，一段完整例題或推導就是一段，不要硬切（b−a 上限 1200 秒、下限 45 秒），不重疊、依時間遞增。why ≤20 字寫「為何值得看」。

## map — 核心，這次的鐵律

### 律一：圖表／表格是主角，文字是補充
每個概念先想「**這用什麼形式表達最快**」：
- 兩個以上東西要分辨 → **compare 比較表**（最優先）
- 有判斷分支、選哪條路 → **mermaid 決策樹**
- 一條推導鏈 → mermaid 由上而下的鏈
- 幾何直觀、電路拓撲 → svg
md 只寫圖表沒講到的補充，bullet 形式、每行 ≤30 字、最多 4 行。**禁止段落式散文，禁止重複圖裡已有的資訊。**

### 律二：mermaid 必須是決策或推導，**禁止名詞分類樹**
**不合格範例**（這只是把名詞掛成樹，bullet 就能講完，沒有存在價值）：
```
A["IV方程式"] --> B["n理想因子"] --> E["沒給取1"]
```
**合格範例**（看到條件就知道走哪條路）：
```
A{"題目給了什麼？"} -->|"給 IS 和 V"| B[["直接代方程式"]]
A -->|"只給參考點"| C[["參考點修正式"]]
A -->|"都沒給"| D[["迭代法"]]
```
判準：**如果這張圖不含任何「判斷」或「因為所以」，就不要畫，改用 compare 表或直接寫 md。**

其他規則：
1. 一張圖 ≤12 節點、≤14 條邊；塞不下就拆成兩個概念各配一張小圖。
2. 節點文字 ≤10 字：名詞或短動詞片語，解釋外移到 md。
3. 樹狀單一方向、不交叉不回繞；判斷分支的邊**必標**（是／否／給了什麼）。
4. 形狀語彙：`(["核心"])`、`["定義／物件"]`、`{"判斷？"}`、`[["方法／操作"]]`、`(("結論"))`。
5. 每張圖結尾附這段 classDef，並用 `class 節點id 類別` 指派到**每一個**節點：
```
classDef core fill:#6D4FC2,stroke:#5A3FA8,color:#fff
classDef defn fill:#2F6DB3,stroke:#265A94,color:#fff
classDef op fill:#2E8B74,stroke:#25735F,color:#fff
classDef warn fill:#B3402F,stroke:#942F23,color:#fff
classDef sup fill:#7A7A7A,stroke:#5E5E5E,color:#fff,stroke-dasharray: 4 3
```
core＝核心概念、defn＝定義、op＝方法操作、warn＝陷阱易錯、sup＝課本補充。
6. 節點文字一律雙引號包住，內部不含括號與分號。

### 律三：compare — 觀念比較表（本次新增，優先使用）
**只要一個概念裡出現「兩種以上要分辨的東西」，就做成比較表，不要用樹也不要用散文。**
典型題材：兩個區域／兩種模型／三種解法／正逆兩種偏壓／兩個定理的適用條件。
- cols 第一欄是**比較軸的名稱**，其餘欄是被比較的對象（2~4 個）。
- rows 每列一個比較軸；軸要選**會影響解題的**：適用條件、公式長相、什麼時候用、誤用會怎樣。
- 每格 ≤18 字。列數 3~6。
- 一個概念至多一張 compare。沒得比就給 null。

### 律四：formulas — 公式卡
把該概念**必背的公式**抽出來（0~3 條），不要只藏在 md 的 bullet 裡。
- tex：純 KaTeX 內容，不含 `$` 符號。
- name ≤12 字；when ≤14 字寫「什麼情況能用」（這比公式本身更常被考）。
- 只收真正要背的；推導中間步驟不算。

### 律五：pitfalls — 錯誤對照（改為三欄）
每條寫成 {wrong, right, why}：wrong 是**具體會寫出來的錯誤**（不是「要小心」這種空話），right 是正確寫法，why ≤20 字。
不合格：`{"wrong":"要注意溫度","right":"用絕對溫度"}` ← wrong 不具體。
合格：`{"wrong":"V_T = 25/11600","right":"V_T = 298/11600","why":"要用絕對溫度K，攝氏加273"}`
只收老師真的警告過或例題真的踩過的，3~8 條。

### 律六：playbook — 題型對照（章節層級）
整堂課的「看到什麼 → 用哪招」，3~8 條，是考場上真正在用的索引。
trigger 寫題目的**可觀察特徵**（給了哪個量、問什麼），method 寫招式名稱。

### sup — 補老師的洞（每堂至少 1~3 個）
老師快速帶過、只點名詞、或說「回去自己看」的地方，用標準教科書補上：
線代 Strang／Friedberg、電子學 Sedra–Smith／Razavi、工數 Kreyszig、控制 Ogata／Kuo。
開頭標「〔補〕」；≤4 行 bullet；獨立可讀；只補考試會考的。
若整個主題老師沒展開但重要，自成一個 concept，mermaid 節點用 sup 類別（虛線灰）。

### trap（concept 層）
一句話 ≤30 字說這個概念最容易錯在哪；沒有就空字串。

### flow / tldr / examples
- flow：本集知識骨架總圖，規則同律二（可以是依賴鏈，不必是判斷）。
- tldr ≤3 條、每條 ≤40 字。
- examples：老師講的例題全收。trigger 寫「題目出現什麼就用這招」；md ≤5 步、每步 ≤24 字，寫**為什麼這步**而非算術；trap 一句話；snap 對應板書 t（沒有給 0）。

## 長度預算（硬上限）
map 的純文字（不含 mermaid／svg／tex 原始碼）合計 **≤1400 字**。超過代表你在轉錄不是消化。
比較表與公式卡不算在內——**它們是要鼓勵你多做的**。

## svg 規則
只畫拓撲簡單但觀念關鍵的示意圖。要有 viewBox、`stroke="currentColor"`、不填死背景色、≤560×320。沒把握就留空，複雜圖交給板書快照。

## 鐵則
- 只輸出 JSON：不要 markdown 圍欄、不要任何前後說明文字。
- 不使用任何工具。
- 所有時間戳落在 0 ~ «DURSEC»。
- 課程內容只能來自逐字稿；**唯一例外是 sup**，且必須標「〔補〕」。
- 數學一律 KaTeX：行內 $...$、獨立 $$...$$（formulas 欄的 tex 不加 $）。臺灣慣用術語。
